# Обзор

**OpenE2E** - это приложение для безопасного обмена зашифрованными сообщениями через любой канал: SMS, электронную почту, мессенджеры, социальные сети или другие ненадежные каналы. Вы зашифровываете сообщения локально на своем устройстве, копируете зашифрованный текст и отправляете его куда угодно. Только вы и получатель сможете расшифровать его.

Приложение использует **Matrix OLM** (через библиотеку `voldozemac`) с **шифрованием AES-256-GCM** и **совершенной прямой секретностью (PFS)**, обеспечивая защиту прошлых сообщений даже если ключи позже будут скомпрометированы. Все данные остаются на вашем устройстве - синхронизации в облаке или хранения на серверах нет.

Для получения технических сведений о модели шифрования см. [OLM.ru.md](./OLM/ru.md).

# Для чего это?

**OpenE2E** позволяет отправлять сообщения через _любой_ канал (текст, электронную почту, социальные сети и так далее) так, чтобы только вы и получатель могли их прочитать. Вы шифруете сообщения на своем устройстве, копируете зашифрованный текст и вставляете его где угодно.

## Почему конфиденциальность важна

**Сбор и анализ данных.** Компании и государственные органы собирают информацию о вашем местоположении, контактах, истории просмотров и поведении онлайн. Эти данные используются для создания профилей, предсказания предпочтений и целевого воздействия. В некоторых случаях они также используются для выявления и отслеживания "проблематичных" групп населения.

**Автоматизированный анализ контента.** С развитием систем машинного обучения появились инструменты, способные автоматически анализировать, категоризировать и фильтровать огромные объемы коммуникаций. Ваши сообщения могут быть просканированы на предмет определенного контента, отмечены алгоритмами или переданы властям. Хотя такие системы пока не совершенны и дают ложные срабатывания, они становятся все более точными и распространенными.

**Что это значит на практике.** Даже если вы не делаете ничего незаконного, ваши частные размышления, планы и мнения могут быть неправильно интерпретированы алгоритмом, извлечены из контекста или использованы против вас позже, например, при устройстве на работу, рассмотрении кредита или в судебном процессе.

**Почему шифрование сквозое шифрование имеет значение:** Когда ваши сообщения зашифрованы, ни компании, ни государственные системы не могут их просканировать или анализировать. Ваша коммуникация остается видна только вам и получателю - вне досягаемости массового мониторинга и алгоритмического анализа.

# Установка

### Вариант 1: Предварительно собранные бинарные файлы

1. Перейдите в [Releases](https://codeberg.org/bazelik-dev/OpenE2E/releases) и скачайте последний бинарный файл для вашей ОС (выберите GUI для графического интерфейса или CLI для консольного интерфейса)
2. Проверьте подпись:
   ```bash
   gpg --auto-key-locate keyserver --keyserver-options auto-key-retrieve --verify OpenE2E*.asc $(find . -maxdepth 1 -name 'OpenE2E*' ! -name '*.asc')
   ```
   Ключ должен совпадать: `C4C5BDC6C5E4C96CF12B3E85B7BBEB3BC5439F72` от `bazelik-dev@proton.me`

### Вариант 2: Сборка с помощью Cargo

```bash
git clone https://codeberg.org/bazelik-dev/OpenE2E.git
cd OpenE2E
cargo build --release
```

Добавьте `--features ui` для включения графического интерфейса Slint:

```bash
cargo build --release --features ui
```

### Вариант 3: Параллельная сборка (все ядра)

Использует скрипт сборки для одновременной компиляции CLI и GUI:

```bash
git clone https://codeberg.org/bazelik-dev/OpenE2E.git
cd OpenE2E
./build.sh
```

**Выходные файлы:**

- CLI: `./OpenE2E-CLI_{linux,windows}/bin/OpenE2E`
- GUI: `./OpenE2E-GUI_{linux,windows}/bin/OpenE2E`

### Вариант 4: Сборка с Nix

```bash
git clone https://codeberg.org/bazelik-dev/OpenE2E.git
cd OpenE2E
./build-nix.sh
```

**Выходные файлы:**

- CLI: `./OpenE2E-CLI_NixOS/bin/OpenE2E`
- GUI: `./OpenE2E-GUI_NixOS/bin/OpenE2E`

Оба бинарных файла включают все зависимости времени выполнения в их директориях `lib/`.

# Как это работает

### Пошаговый процесс

1. **Создайте сеанс** - Начните новый разговор в приложении
2. **Обменяйтесь открытыми ключами** - Сгенерируйте ваш эфемерный открытый ключ и поделитесь им с контактом через любой канал
3. **Получите их ключ** - Вставьте открытый ключ вашего контакта в приложение для установления сеанса
4. **Зашифруйте и скопируйте** - Напишите ваше сообщение, и приложение локально зашифрует его и даст вам шифротекст
5. **Отправьте шифротекст** - Скопируйте и вставьте зашифрованное сообщение через электронную почту, SMS, социальные сети или другой канал
6. **Получите и расшифруйте** - Вставьте зашифрованное сообщение, которое отправил вам контакт, в приложение
7. **Прочитайте локально** - Приложение расшифрует его на вашем устройстве и отобразит в чате
8. **Продолжайте** - Повторяйте для продолжения безопасной коммуникации

**Ключевое преимущество:** Вы контролируете транспорт. OpenE2E обрабатывает шифрование, вы перемещаете зашифрованные данные.

# Архитектура

OpenE2E следует паттерну **разделения ответственности** с четким разделением бэкенд/фронтенд и паттерном объект/менеджер.

### Структура проекта

```
src/
├── backend/                   # Основная логика
│   ├── managers/              # Менеджеры обрабатывают операции с объектами
│   │   ├── user_manager.rs    # Создание аккаунта пользователя, аутентификация
│   │   ├── session_manager.rs # Создание сеанса, обмен ключами, состояние
│   │   ├── storage_manager.rs # Операции с базой данных
│   │   └── mod.rs
│   └── objects/               # Модели данных
│       ├── user.rs            # Данные аккаунта пользователя
│       ├── session.rs         # Состояние сеанса, ключи, криптография
│       ├── message.rs         # Структуры данных сообщений
│       └── mod.rs
│
├── frontend/                  # UI и взаимодействие с пользователем
│   ├── cli/                   # Командная строка
│   ├── gui/                   # Графический интерфейс
│   │   └── slint/             # Макет UI Slint
│   ├── fluent_manager.rs      # Система локализации
│   ├── logger.rs              # Логирование
│   └── mod.rs
│
├── error_mapper.rs            # Преобразование ошибок в строки
├── main.rs                    # Точка входа
└── tests/                     # Модульные и интеграционные тесты
```

### Паттерн дизайна

**Backend (Объекты + Менеджеры):**

- **Объекты** (`user.rs`, `session.rs`, `message.rs`) представляют экземпляры данных
- **Менеджеры** (`user_manager.rs`, `session_manager.rs`, `storage_manager.rs`) обрабатывают все операции с объектами
- Менеджеры взаимодействуют с хранилищем и выполняют логику шифрования/расшифровки
- Четкое разделение гарантирует, что логика бэкенда независима от UI

**Frontend (CLI + GUI):**

- **CLI** предоставляет интерфейс командной строки
- **GUI** использует Slint для нативного, легкого интерфейса
- Оба фронтенда вызывают одни и те же менеджеры бэкенда, обеспечивая одинаковое поведение
- `fluent_manager.rs` обрабатывает локализацию

### Ключевые преимущества дизайна

- **Модульность** - Бэкенд может использоваться CLI, GUI или другими фронтендами без изменений
- **Удобство обслуживания** - Основная логика изолирована от кода UI
- **Локализация** - Строки текста централизованы в директории `locales/`

# Защита данных

- **Сеансы и аккаунты:** Зашифрованы в fjall DB с помощью AES-256-GCM
- **Сообщения:** Зашифрованы в хранилище с помощью AES-256-GCM и случайного nonce
- **Пароли:** Используются только для получения ключей шифрования. Они никогда не сохраняются
- **Только локально:** Без синхронизации облака, без хранения на серверах, без доступа третьих лиц

# Функциональность

- **Безопасный чат вручную** - Обменивайтесь зашифрованными сообщениями посредством копирования и вставки через любой канал
- **Соврешенная прямая секретность** - Прошлые сообщения остаются защищенными даже если ключи позже скомпрометированы
- **Сквозное шифрование** - Сообщения зашифрованы локально. Только отправитель и получатель могут их прочитать
- **Работает через любой канал** - SMS, электронная почта, мессенджеры, социальные платформы, государственные сервисы и т.д.
- **Только локальное хранилище** - Все данные остаются на вашем устройстве
- **Шифрование AES-256-GCM** - Промышленное шифрование для сообщений и хранилища сеансов
- **Двойной интерфейс** - CLI для опытных пользователей и Termux. GUI для общего использования
- **Многоязычность** - Английская и Русская локализация
- **На базе Rust** - Безопасно для памяти, молниеносно быстро и защищенно

# Часто задаваемые вопросы

**В: Зачем использовать это вместо Signal, WhatsApp или Telegram?**

О: Эти приложения требуют специальных приложений на обеих сторонах и контролируют транспорт. OpenE2E позволяет отправлять зашифрованные сообщения через _любой_ канал, который вы уже используете - вашу существующую электронную почту, SMS, социальные сети и т.д. Обеим сторонам не нужно устанавливать ничего особенного. Это полезно, когда:

- Прямой безопасный транспорт недоступен
- Вы хотите добавить шифрование к существующим каналам коммуникации
- Вам нужно "просто копировать-вставлять" зашифрованные сообщения
- Вы предпочитаете контролировать транспорт

**В: Поддерживает ли OpenE2E вложение файлов?**

О: Пока нет. Поддержка файлов находится в [Дорожной карте](#дорожная-карта).

**В: Могу ли я импортировать/экспортировать свои сообщения, сеансы и аккаунты?**

О: В настоящее время сообщения хранятся только в локальной зашифрованной базе данных. Поддержка импорта/экспорта хранилища находится в [Дорожной карте](#дорожная-карта).

**В: Что происходит, если я забуду свой пароль?**

О: Ваш пароль используется для получения ключей шифрования для вашей базы данных. Если вы его забудете, ваши сообщения и сеансы не смогут быть восстановлены. Нет механизма сброса пароля или восстановления.

**В: Безопасны ли мои данные, если мое устройство скомпрометировано?**

О: Ваши сообщения зашифрованы с помощью AES-256-GCM, и ключи шифрования получены из вашего пароля с использованием Argon2. Если злоумышленник получит доступ к вашему устройству, сохраненные сообщения остаются зашифрованными и не могут быть прочитаны без вашего пароля.

Однако, если злоумышленник может получить доступ к вашему устройству, пока вы вошли в систему, он может прочитать содержимое сообщений в памяти. Это общее ограничение любой локальной системы.

**В: Могут ли разработчики видеть мои сообщения?**

О: Нет. OpenE2E работает полностью на вашем устройстве. Нет серверов, нет аккаунтов на внешних сервисах и нет способа для разработчиков получить доступ к вашим данным. Исходный код открыт для вас, чтобы вы могли это проверить.

**В: Как мне проверить личность открытого ключа моего контакта?**

О: OpenE2E не проверяет автоматически ключи (это практически невозможно без надежного канала). Вы должны проверить личность открытого ключа вашего контакта через отдельный, надежный канал.

**В: Что, если я потеряю файл зашифрованной базы данных?**

О: Ваш файл зашифрованной базы данных (хранящийся локально) содержит все ваши сообщения и ключи сеансов. Если вы его удалите или потеряете, эти сообщения не смогут быть восстановлены. Создайте резервную копию файла зашифрованной базы данных в безопасном месте, если вы хотите сохранить историю сообщений.
